# Принятые решения и допущения

Этот документ фиксирует решения, которые не должны переосмысливаться во время реализации без отдельного согласования.

## Продукт

| Решение | Значение |
|---|---|
| Отображаемое название | MCSR Сабинск |
| Технический идентификатор | `mcsr-sabinsk` |
| Язык первой версии | русский |
| Часовой пояс интерфейса | `Europe/Moscow`, UTC+3 |
| Количество дивизионов | всегда 3 |
| Названия дивизионов | Новички, Опытные, Про |
| Участие | один участник — один дивизион в рамках турнира |
| Управление | закрытая админ-панель |
| Источник квалификационных матчей | ручной ввод Ranked `match_id` |
| Исторические данные | сохраняются в PostgreSQL |

## Турниры

- Турниры создаются вручную и не имеют недельной периодичности.
- В переключателе показываются название и даты, доступны стрелки и выпадающий список.
- Статусы: `DRAFT`, `UPCOMING`, `QUALIFICATION`, `PLAYOFF`, `COMPLETED`.
- Черновик не виден публично.
- Предстоящие турниры видны публично.
- Завершённый турнир является заблокированным историческим снимком.
- Корректирующий повторный импорт после завершения разрешён администратору после явного подтверждения и создаёт запись аудита.

## Квалификация

- Ник вводится вручную и проверяется через `GET /users/{identifier}` Ranked API.
- В базе главным внешним идентификатором игрока является UUID, ник хранится как актуальный снимок.
- Пользователи Ranked-матча, не зарегистрированные в дивизионе, игнорируются.
- Для формулы `P` — количество зарегистрированных участников дивизиона, фактически участвовавших в конкретном матче.
- Пропустивший матч получает 0 очков и эффективное время, равное лимиту дивизиона, но не увеличивает `P`.
- DNF получает 0 очков и эффективное время, равное лимиту.
- DNF наступает при отсутствии `completion` либо при времени финиша больше лимита.
- Тай-брейк: очки по убыванию, среднее время по возрастанию, ник по возрастанию.
- Ручных штрафов, бонусов и дисквалификаций в первой версии нет.

## Плей-офф

- У каждого дивизиона своя независимая сетка.
- В первой версии поддерживаются размеры 4, 8 и 16.
- Администратор сам выбирает участников и пары.
- Счёт вводится вручную.
- Администратор сам перемещает участников в следующие раунды.
- Автоматической проверки формата серии и автоматического продвижения нет.
- Матч за третье место опционален для каждой сетки.
- Публично показывается только сетка; расписание, призы и отдельный список игроков не входят в первую версию.
- Матчи плей-офф не связаны с Ranked `match_id`.

## Технологии

| Область | Решение |
|---|---|
| Репозиторий | монорепозиторий |
| Workspace/package manager | pnpm workspaces через Corepack |
| Язык | TypeScript |
| Runtime backend | Node.js LTS |
| Frontend | Astro + React |
| Стили | Tailwind CSS + shadcn/ui |
| Backend | NestJS |

| База | PostgreSQL |

| Время в БД | UTC |

## Структура монорепозитория

```text
apps/
  frontend/
    src/
  backend/
    src/
packages/
  shared/
documentation/
```

`packages/shared` содержит только независимые TypeScript-типы, перечисления и Zod-схемы, которые не импортируют NestJS, Prisma, Astro или React.

## Допущения

- Штатный размер дивизиона — до 100 участников.
- Штатное число квалификационных матчей дивизиона — до 50.
- Одновременная работа нескольких администраторов редка, но конфликтующие записи защищаются optimistic locking.
- Публичные посетители не создают данные.
- Ranked API не требует приватного ключа для используемых endpoints.
- Обложки хранятся вне PostgreSQL; в базе хранится URL и метаданные.
- Minecraft-шрифты и визуальные ресурсы аналога используются только после проверки права на распространение.

## Требующие решения не раньше второй версии

- Discord OAuth и Discord-бот;
- роли администратора и редактора;
- автоматическое создание посева;
- автоматическое продвижение победителей;
- расписание плей-офф;
- live-матчи;
- ручные санкции;
- мультиязычность.
