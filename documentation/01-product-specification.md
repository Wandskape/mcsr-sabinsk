# Продуктовая спецификация

## 1. Назначение

**MCSR Сабинск** (`mcsr-sabinsk`) — русскоязычное веб-приложение для публикации квалификаций и плей-офф турниров по Minecraft Speedrunning Ranked.

Приложение должно:

- показывать предстоящие, текущие и завершённые турниры;
- поддерживать три доступных дивизиона, из которых в конкретном турнире участвуют один, два или три;
- импортировать завершённые квалификационные матчи по MCSR Ranked `match_id`;
- рассчитывать очки, среднее время и лидерборд;
- сохранять исторические данные независимо от доступности Ranked API;
- показывать подробности участника и прохождение квалификационного матча;
- показывать вручную управляемую сетку плей-офф;
- публиковать отдельную страницу с актуальными правилами и форматом турнира;
- предоставлять закрытую админ-панель.

## 2. Границы первой версии

### Входит в первую версию

- русскоязычный публичный интерфейс;
- один тип администратора;
- вход по логину и паролю;
- CRUD турниров;
- загрузка обложки;
- от одного до трёх участвующих дивизионов;
- индивидуальный лимит времени каждого дивизиона;
- ручная регистрация участников с проверкой через Ranked API;
- пакетное добавление списка ников;
- импорт и повторный импорт матчей по `match_id`;
- автоматический расчёт квалификационного лидерборда;
- карточка участника в контексте выбранного турнира и дивизиона;
- сохранённая timeline-визуализация матча;
- ручные сетки плей-офф на 4, 8 или 16 участников;
- опциональный матч за третье место;
- публичная страница правил;
- журнал значимых административных действий.
- экспорт одного или всех турниров в переносимый ZIP и восстановление через
  предварительно проверенный импорт.

### Не входит в первую версию

- самостоятельная регистрация игроков;
- Discord OAuth;
- несколько административных ролей;
- ручные штрафы, бонусы и дисквалификации;
- автоматический поиск матчей;
- live-отслеживание незавершённого матча;
- автоматическое формирование пар первого раунда;
- расписание плей-офф;
- призы и итоговый пьедестал;
- история участника по всем турнирам в его карточке;
- локализация на другие языки;
- мобильное приложение;
- интеграция с Discord-ботом.

## 3. Пользователи

### Публичный посетитель

Может без авторизации:

- выбрать турнир;
- перейти между дивизионами;
- увидеть статус и даты турнира;
- просмотреть лидерборд и список квалификационных матчей;
- открыть карточку участника;
- открыть сохранённые подробности матча;
- переключиться на сетку плей-офф, если она опубликована.

### Администратор

После входа может:

- создавать, редактировать и публиковать турниры;
- управлять обложкой;
- задавать лимиты дивизионов;
- добавлять и удалять участников;
- импортировать и повторно импортировать матчи;
- создавать сетки плей-офф;
- вручную расставлять прошедших участников первого раунда и вводить счёт;
- автоматически продвигать победителей и проигравших полуфиналов в связанные
  позиции следующих раундов;
- завершать турнир;
- выполнять корректирующий импорт завершённого турнира после подтверждения;
- просматривать журнал аудита.

## 4. Структура турнира

Для каждого турнира создаются три доступных дивизиона:

1. **Новички**;
2. **Опытные**;
3. **Про**.

В квалификацию входят только дивизионы, в которых на момент старта есть зарегистрированные участники. Поэтому конкретный турнир может проводиться в одном, двух или трёх дивизионах. Зафиксированный при старте состав участвующих дивизионов сохраняется в истории турнира.

Один участник может быть зарегистрирован только в одном дивизионе конкретного турнира. В разных турнирах его дивизион может отличаться.

Турнир содержит:

- название;
- уникальный URL-идентификатор `slug`;
- описание;
- дату и время начала;
- дату и время окончания;
- статус;
- признак публичной публикации, выраженный статусом;
- обложку;
- от одного до трёх участвующих дивизионов;
- квалификационные матчи;
- отдельную опциональную сетку плей-офф для каждого дивизиона.

## 5. Жизненный цикл

Допустимые статусы:

1. **Черновик** — доступен только в админ-панели.
2. **Предстоящий** — публично опубликован, квалификация ещё не началась.
3. **Квалификация** — публичный лидерборд обновляется импортами матчей.
4. **Плей-офф** — квалификация закончена, доступны лидерборд и опубликованные сетки.
5. **Завершён** — публичный исторический турнир.

Обычные переходы:

`Черновик → Предстоящий → Квалификация → Плей-офф → Завершён`

Возврат на предыдущий статус доступен администратору до завершения и фиксируется в аудите. После завершения обычное редактирование блокируется; корректирующие операции выполняются отдельными командами с подтверждением.

## 6. Публичный пользовательский путь

1. Посетитель открывает страницу турниров.
2. По умолчанию выбирается турнир с наивысшим приоритетом:
   - текущий в квалификации или плей-офф;
   - ближайший предстоящий;
   - последний завершённый.
3. Посетитель может листать турниры стрелками или выбрать их из списка.
4. Он выбирает дивизион.
5. В режиме «Квалификация» видит таблицу и список матчей.
6. Нажатие на участника открывает подробности его результатов этого турнира.
7. Нажатие на матч открывает сохранённые результаты и timeline.
8. Если для дивизиона опубликована сетка, рядом доступен переключатель «Плей-офф».

## 7. Основные нефункциональные требования

- Публичные данные должны открываться без запроса к Ranked API.
- Повторный импорт не должен оставлять частично пересчитанные данные.
- Время хранится в UTC, показывается в `Europe/Moscow`.
- Публичная страница должна корректно работать от 360 px ширины.
- Админские операции должны быть идемпотентными там, где это возможно.
- История административных исправлений должна быть доступна для проверки.
- Основные публичные запросы должны укладываться в 500 мс на сервере при штатном объёме данных.

## 8. Критерии готовности продукта

Первая версия считается готовой, когда администратор может без доступа к базе:

1. создать и опубликовать турнир;
2. заполнить состав хотя бы одного дивизиона и задать лимиты;
3. зарегистрировать участников;
4. импортировать несколько Ranked-матчей;
5. увидеть корректно пересчитанный лидерборд;
6. повторно импортировать исправленный матч;
7. создать сетку каждого нужного размера;
8. вручную заполнить пары первого раунда и результаты; последующие пары
   заполняются по победителям автоматически;
9. завершить турнир;
10. открыть все опубликованные данные из публичного интерфейса после отключения Ranked API.
