# Сценарии администратора

## 1. Вход

1. Администратор открывает `/admin/login`.
2. Вводит логин и пароль.
3. При успехе создаётся серверная сессия.
4. Пользователь попадает на список турниров.
5. После нескольких неверных попыток вход временно блокируется.

В интерфейсе нет восстановления пароля по email. Сброс выполняется серверной CLI-командой с доступом к production-окружению.

## 2. Создание турнира

1. Нажать «Создать турнир».
2. Заполнить:
   - название;
   - slug;
   - описание;
   - даты;
   - лимиты Новичков, Опытных и Про.
3. Сохранить черновик.
4. Загрузить обложку.
5. Проверить preview публичной карточки.
6. Перевести в «Предстоящий».

Backend создаёт три доступных типа дивизиона автоматически. Добавлять четвёртый тип нельзя. Конкретный турнир может стартовать с одним, двумя или тремя дивизионами.

## 3. Добавление участников

### Один участник

1. Открыть нужный дивизион.
2. Ввести ник.
3. Нажать «Проверить в Ranked».
4. Увидеть подтверждённый ник и UUID.
5. Подтвердить добавление.

Ошибки:

- профиль не найден;
- UUID уже зарегистрирован в другом дивизионе этого турнира;
- ник совпал, UUID отличается;
- Ranked API недоступен.

### Список участников

1. Вставить по одному нику на строку.
2. Запустить проверку.
3. Получить preview:
   - готовые к добавлению;
   - уже зарегистрированные;
   - не найденные;
   - конфликтующие.
4. Исправить ошибки либо исключить строки.
5. Применить подтверждённый список одной транзакцией.

## 4. Запуск квалификации

Перед переходом в `QUALIFICATION` админ-панель показывает checklist:

- турнир опубликован;
- даты корректны;
- обложка загружена;
- лимиты заданы;
- составы проверены;
- нет участника в двух дивизионах.

Для старта достаточно хотя бы одного непустого дивизиона. При подтверждении перехода все непустые дивизионы фиксируются как участвующие, а пустые получают статус «Не участвует». После первого импорта состав соответствующего участвующего дивизиона фиксируется.

## 5. Импорт квалификационного матча

1. Открыть дивизион → «Квалификация».
2. Нажать «Импортировать матч».
3. Ввести Ranked `match_id`.
4. Backend получает данные и показывает preview:
   - номер/дату Ranked-матча;
   - найденных зарегистрированных игроков;
   - пропустивших;
   - DNF;
   - проигнорированных наблюдателей/хостов;
   - места и очки;
   - будущего победителя;
   - предупреждения.
5. Администратор подтверждает импорт.
6. После применения интерфейс показывает новую строку матча и обновлённый лидерборд.

Импорт запрещается, если:

- Ranked-матч не найден;
- ответ неполон;
- менее двух зарегистрированных игроков участвовали;
- ID уже принадлежит другому дивизиону;
- турнир находится в недопустимом статусе;
- preview устарел.

## 6. Повторный импорт

1. Открыть существующий матч.
2. Нажать «Получить данные заново».
3. Сравнить старую и новую версию:
   - добавленные/удалённые участники;
   - изменения статуса;
   - времени;
   - места;
   - очков;
   - изменения итогового лидерборда.
4. Подтвердить замену.
5. Backend применяет полный снимок и пересчёт.

Если payload не изменился, интерфейс сообщает «Изменений нет».

## 7. Коррекция завершённого турнира

1. Открыть завершённый турнир.
2. Включить режим «Коррекция истории».
3. Выбрать матч.
4. Получить новый preview.
5. Ввести причину.
6. Установить явный checkbox подтверждения.
7. Применить.
8. Проверить пересчитанный лидерборд и созданную запись аудита.

Турнир остаётся в статусе `COMPLETED`.

## 8. Создание плей-офф

Для каждого дивизиона отдельно:

1. Перевести турнир в `PLAYOFF`.
2. Открыть дивизион → «Плей-офф».
3. Выбрать размер: 4, 8 или 16.
4. Включить или выключить матч за третье место.
5. Создать черновик сетки.
6. Выбрать участников из регистраций дивизиона.
7. Вручную расставить пары первого раунда.
8. Проверить preview.
9. Опубликовать.

Система фиксирует top-N квалификации по очкам, среднему времени, нику и Ranked
UUID. Администратор вручную составляет пары первого раунда только из этих
участников.
Размер сетки после создания не меняется. Публикация доступна после заполнения
обоих участников во всех парах первого раунда.

## 9. Ведение плей-офф

Для каждого матча:

1. Выбрать или проверить двух участников.
2. Ввести два значения счёта.
3. Выбрать победителя.
4. Сохранить матч.
5. Система автоматически переносит победителя в связанную позицию следующего
   раунда.

При исправлении раннего матча система:

- меняет связанную позицию следующего раунда;
- сбрасывает счёт и победителя затронутого матча;
- каскадно очищает устаревшее продвижение;
- возвращает обновлённую сетку администратору.

## 10. Матч за третье место

- Флаг можно переключать до завершения турнира.
- При включении появляется отдельная пара.
- Участников назначает администратор.
- При выключении пара исчезает из публичного интерфейса, но сохраняется в админке.

## 11. Завершение

Checklist:

- статус допускает завершение;
- нет незавершённых импортов;
- для участвующих дивизионов сохранены результаты квалификации;
- если созданы сетки, турнир переведён в `PLAYOFF`;
- все отображаемые матчи опубликованных сеток завершены;
- неопубликованные сетки явно показаны как предупреждение.

Кнопка завершения сначала открывает modal checklist. Блокирующая ошибка отключает
подтверждение; предупреждение требует внимания, но не запрещает завершение.
Backend повторяет проверки при записи. После подтверждения турнир становится
историческим, а обычные операции изменения блокируются.

## 12. Журнал аудита

В журнал попадают:

- входы и блокировки входа;
- создание и изменение турнира;
- переходы статусов;
- изменение состава после фиксации;
- импорт и повторный импорт;
- коррекция завершённого турнира;
- создание, публикация и изменение сетки;
- изменение счёта и победителя;
- загрузка/замена обложки.

Для каждого события показываются администратор, время МСК, действие, сущность, причина и безопасный diff.

Страница `/admin/audit` позволяет фильтровать журнал по действию, типу и ID
сущности, администратору и диапазону дат. Список загружается страницами по
cursor. Выбор события открывает `requestId` и построчное сравнение снимков
`before`/`after`.
