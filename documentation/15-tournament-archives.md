# Экспорт и импорт турниров

## 1. Назначение

Переносимый архив позволяет сохранить турнирные данные перед остановкой
хостинга и позднее восстановить их на чистом экземпляре MCSR Сабинск. Это
прикладной экспорт и не заменяет полный backup PostgreSQL и MinIO перед
обновлением работающего сервера.

Экспорт разрешён для турниров любого статуса, включая черновики и
незавершённые турниры.

## 2. Состав архива

ZIP содержит:

- `manifest.json` с версией формата, датой экспорта и SHA-256 `data.json`;
- `data.json` со всеми выбранными турнирами;
- обложки в каталоге `covers/` с индивидуальными SHA-256.

Для каждого турнира сохраняются:

- основные поля и статус;
- дивизионы и их лимиты;
- снимки участников и регистрации;
- квалификационные матчи;
- все версии Ranked-импортов, включая raw payload;
- результаты, очки, времена и timeline;
- сетки, посевы и матчи плей-офф;
- связанные записи аудита с исходным именем администратора;
- обложка.

Не экспортируются администраторы, password hash, сессии, CSRF/session secrets,
переменные окружения и другие серверные секреты.

## 3. Административные операции

- У выбранного турнира доступна команда «Экспортировать».
- Над списком доступна команда «Экспортировать все», создающая один ZIP.
- Импорт начинается с выбора ZIP и обязательного preview.
- Preview показывает версию, контрольную сумму, размер, количество турниров,
  участников, матчей, обложек и записей аудита, а также результат проверки
  каждого турнира.
- Только после успешного preview администратор подтверждает импорт.

Экспорт не удаляет и не меняет данные.

## 4. Конфликты

Для каждого турнира preview возвращает:

- `READY` — можно импортировать;
- `ALREADY_IMPORTED` — турнир с тем же внутренним ID уже существует и будет
  пропущен;
- `CONFLICT` — обнаружено несовместимое совпадение.

Конфликтом считается:

- существующий турнир с таким же slug, но другим ID;
- существующий квалификационный матч с тем же Ranked match ID;
- пересечение внутренних ID с чужими сущностями;
- совпадение ID участника с другим Ranked UUID;
- повреждение структуры или контрольных сумм архива.

При наличии хотя бы одного `CONFLICT` весь импорт блокируется. Автоматической
замены существующих турниров нет.

Одинаковый Ranked UUID участника не является конфликтом: новая регистрация
связывается с уже существующим глобальным участником.

## 5. Атомарность

Все записи PostgreSQL для подтверждённого архива создаются одной транзакцией.
Турниры со статусом `ALREADY_IMPORTED` пропускаются, остальные восстанавливаются
с исходными идентификаторами.

Обложки загружаются в S3 перед транзакцией под ключами
`covers/imported/<tournamentId>.<extension>`. При ошибке записи БД турнир не
появляется, а уже загруженные объекты удаляются компенсирующей операцией.

Старые записи аудита связываются с администратором, выполнившим восстановление,
но отображают сохранённое исходное имя автора. Дополнительно создаётся событие
`TOURNAMENT_ARCHIVE_IMPORTED`.

## 6. Ограничения и совместимость

- Текущая версия формата: `1`.
- Максимальный размер загружаемого ZIP: 100 МБ.
- Максимальный размер распакованного `data.json`: 75 МБ.
- Неподдерживаемая версия формата отклоняется до изменения данных.
- После обновления формата старые версии должны либо поддерживаться отдельным
  преобразователем, либо отклоняться с понятным сообщением.

## 7. API

Все маршруты требуют активную административную сессию.

```text
GET  /api/v1/admin/tournament-archives/:id/export
GET  /api/v1/admin/tournament-archives/export-all
POST /api/v1/admin/tournament-archives/preview
POST /api/v1/admin/tournament-archives/import
```

Обе POST-команды принимают `multipart/form-data`, требуют CSRF-токен и поле
`file`. Импорт дополнительно принимает `archiveChecksum`, полученный из preview,
и повторно проверяет SHA-256 файла.
