# UI/UX-спецификация

## 1. Визуальное направление

Интерфейс повторяет настроение MSCL:

- почти чёрный фон;
- приглушённые серые поверхности;
- зелёный акцент;
- Minecraft-пиксельный шрифт для заголовков, ников, табов и чисел;
- Inter для длинного текста и форм;
- тонкие границы;
- крупные скругления панелей;
- минимальное количество декоративных элементов.

Точное копирование логотипов MCSR Ranked запрещено. MCSR Сабинск использует собственную текстовую марку.

## 2. Типографика

- Заголовки: Minecraft font, 700.
- Ники и позиции: Minecraft font, 400/700.
- Основной текст и формы: Inter Variable.
- Минимальный размер основного текста: 14 px.
- Табличные числа используют `font-variant-numeric: tabular-nums`.

Перед включением WOFF-файлов аналога проверяется лицензия.

## 3. Цветовые роли

Базовая палитра задаётся design tokens, не жёсткими цветами в компонентах:

- `background`;
- `surface`;
- `surface-muted`;
- `foreground`;
- `muted-foreground`;
- `border`;
- `primary`;
- `success`;
- `warning`;
- `danger`;
- цвета восьми timeline-фаз.

Контраст текста соответствует WCAG AA.

## 4. Публичные маршруты

```text
/                         → выбранный по умолчанию турнир
/tournaments/:slug        → конкретный турнир
/tournaments/:slug?division=beginner&view=qualification
/tournaments/:slug?division=pro&view=playoff
```

URL хранит:

- slug турнира;
- дивизион;
- режим `qualification` или `playoff`.

Выбранный участник или матч может храниться в query `details`, чтобы ссылку можно было отправить, но закрытие панели очищает параметр.

## 5. Верхняя часть страницы

### Навигация

В первой версии:

- текстовый логотип «MCSR Сабинск»;
- ссылка «Турниры»;
- без ссылок на отсутствующие страницы.

### Заголовок турнира

Показывает:

- название;
- даты в МСК;
- статус;
- краткое описание;
- обложку в компактном hero-блоке.

### Переключатель турниров

- стрелка назад;
- центральное название и диапазон дат;
- стрелка вперёд;
- кнопка выпадающего списка всех публичных турниров.

Порядок: по `startsAt` по убыванию. Стрелка недоступна на границе списка.

## 6. Дивизионы и режим

Desktop:

- до старта доступны вкладки «Новички», «Опытные», «Про»;
- после старта публично показываются только участвующие дивизионы;
- в админ-панели пустой дивизион, не вошедший в турнир, остаётся видимым с отметкой «Не участвует».

Mobile:

- select или горизонтально прокручиваемые вкладки.

Если сетка опубликована, показывается сегмент:

- «Квалификация»;
- «Плей-офф».

Если сетки нет, сегмент «Плей-офф» скрыт.

## 7. Квалификация на desktop

Трёхколоночная компоновка:

1. лидерборд;
2. список матчей;
3. контекстная панель.

### Лидерборд

Строка:

- место;
- ник;
- очки.

Среднее время не выводится в основной строке, чтобы сохранить простоту референса. Оно используется для тай-брейка и доступно в карточке участника.

Состояния:

- hover;
- selected;
- keyboard focus;
- skeleton;
- пустой дивизион.

### Список матчей

Строка:

- «Матч N»;
- иконка короны;
- победитель или «Нет финишировавших».

Матчи сортируются по `matchNumber`.

## 8. Окно участника

Повторяет [окно_участника.png](окно_участника.png).

Содержимое:

- `#место ник`;
- сумма очков;
- число матчей;
- разделитель;
- строка каждого квалификационного матча:
  - номер;
  - место, DNF или «Не участвовал»;
  - полученные очки.

Цвета:

- первое место — золото;
- второе/третье — светлый акцент;
- DNF и пропуск — muted;
- очки — muted.

Ник является ссылкой на `https://mcsrranked.com/stats/{uuid}`.

Показываются только данные выбранного турнира и дивизиона.

## 9. Окно результата

Повторяет [окно_результата.png](окно_результата.png).

Каждая строка содержит:

- Minecraft-голову;
- ник;
- время или лимит/последнее время;
- статус `финиш`, текущая фаза, `DNF` или `не участвовал`;
- цветную timeline-полосу.

Сортировка:

1. COMPLETED по времени;
2. DNF по достигнутой фазе и последнему времени;
3. MISSED.

Tooltip сегмента:

- русское название фазы;
- длительность;
- время начала.

Источник — сохранённый снимок backend. Публичное окно не вызывает Ranked API.

## 10. Mobile квалификация

- Лидерборд и матчи становятся вкладками.
- Подробности открываются в bottom drawer.
- Drawer имеет заголовок, кнопку закрытия и прокрутку.
- Высота не превышает доступный viewport.
- Выбор другого участника или матча заменяет содержимое.

## 11. Плей-офф

Сетка визуально следует [playoff.png](playoff.png):

- отдельная колонка каждого раунда;
- соединительные линии;
- карточка пары с двумя участниками и счётом;
- победитель выделен зелёным;
- пустые будущие позиции показывают «Ожидается»;
- финал визуально отделён;
- матч за третье место расположен рядом с финалом или под ним.

В административном редакторе:

- списки первого раунда содержат только зафиксированный top-N квалификации;
- списки имеют тёмный фон и контрастный текст;
- поле счёта имеет постоянную подпись и заметную границу;
- участники последующих раундов и матча за третье место показываются как
  автоматически назначенные, без выбора произвольного игрока.

Названия раундов:

| Размер | Раунды |
|---:|---|
| 4 | Полуфиналы → Финал |
| 8 | Четвертьфиналы → Полуфиналы → Финал |
| 16 | 1/8 финала → Четвертьфиналы → Полуфиналы → Финал |

На узком экране сетка имеет горизонтальную прокрутку. Масштаб не должен делать текст мельче 12 px.

## 12. Предстоящий турнир

Для `UPCOMING`:

- показываются обложка, название, описание и даты;
- лидерборд может показывать зарегистрированных участников без мест и очков;
- матчи отсутствуют;
- текст «Квалификация ещё не началась».

Черновик недоступен публично.

## 13. Админ-панель

Маршруты:

```text
/admin/login
/admin/tournaments
/admin/tournaments/new
/admin/tournaments/:id
/admin/tournaments/:id/divisions/:divisionId
/admin/tournaments/:id/divisions/:divisionId/playoff
/admin/audit
```

Основные принципы:

- формы с autosave не используются для критических операций;
- destructive/corrective действия требуют modal confirmation;
- preview импорта обязателен;
- score и winner сохраняются одной командой;
- несогласованности сетки видны до публикации;
- статусы показываются текстом и цветом, а не только цветом.

### Завершение турнира

Кнопка завершения открывает modal с финальным checklist. Каждая строка имеет
текстовый статус и иконку: выполнено, предупреждение или блокирующая ошибка.
Кнопка подтверждения недоступна при любой блокирующей ошибке. Текст сообщает,
что после завершения обычное редактирование будет заблокировано.

### Журнал аудита

`/admin/audit` состоит из фильтров, cursor-списка событий и панели деталей.
Панель показывает метаданные, причину и таблицу diff «поле / до / после». На
узком экране панели располагаются вертикально, а широкая таблица diff
прокручивается внутри контейнера.

## 14. Состояния ошибок

- Ошибка Ranked API не очищает форму.
- Пользователю показывается понятное русское сообщение и возможность повтора.
- `409` предлагает обновить страницу и сравнить изменения.
- Ошибка импорта показывает `requestId`, который можно передать разработчику.
- Публичная страница при ошибке API backend показывает сохранённый retry state, а не пустой экран.

## 15. Доступность

- Все строки-кнопки доступны с клавиатуры.
- Drawer удерживает focus и возвращает его после закрытия.
- Tab/Select имеют корректные ARIA-роли.
- Timeline имеет текстовый эквивалент.
- Аватары имеют alt с ником.
- `prefers-reduced-motion` отключает необязательные анимации.
